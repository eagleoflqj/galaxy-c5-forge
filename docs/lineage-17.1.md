# LineageOS 17.1 bring-up

## Scope

The Android 10 / LineageOS 17.1 adaptation milestone is CLOSED on 2026-10-08 for the designated SM-C5000/c5lte/CSA1 device and the owner's selected no-SIM use. The owner confirms all three final requested groups pass on installed RIL Parcel repair ROM SHA-256 `daff6dce9a65b162e4b77753ab04aa200220cfe62960ed6e2cda1154770cbaa4`: sustained cable-free power-off and power-key cold boot with automatic Wi-Fi reconnect and usable networking; Bluetooth headset playback, headset off/on automatic reconnect and resumed playback; and a harmless MTP file round trip with matching content. Exact elapsed time, filename and transfer checksums were not supplied and are not inferred. Fresh ordinary-shell checks corroborate normal boot-complete/stopped Android, normal-system selection, `shutdown,userrequested` boot reasons, enforcing SELinux, writable ext4 data/cache mounts and expected capacities. No selected functional area remains FAIL. Remaining untested paths and SELinux warnings are explicit limitations, not implied passes. Independent clean rebuilding, CI and byte-identical reproduction remain separate open project work.

This is the Android 10 migration track for the designated Samsung SM-C5000 (`c5lte`). It reuses the hardware-tested LineageOS 16 device, Linux 3.10.108 kernel and proprietary-vendor baselines while moving the platform and Samsung common hardware project to pinned LineageOS 17.1 revisions. The automatic-ADB and PMIC-storage recovery is installed and verified, and Android 10 completes boot to the desktop under enforcing SELinux. The installed Bluetooth hybrid combines Android 10's service executable with the proven QTI Pronto SMD/NVM implementation and passes controller initialization, discovery, pairing, media playback and reconnect. The concrete SCO-route and normal-system legacy-FunctionFS replacements are installed; Sound settings remains responsive, and system ADB passes cable-free reboot and adbd-restart tests.

## Source adaptations

- The four common c5lte patches retain the device-verified boot addresses, CSA1 bootloader assertion, complete ADSP firmware link set, exact CSA1 GNSS stack and exact matched sensor firmware/HAL pair.
- Android 10 rejects the obsolete `eng` module tag. The common patch retains the Android 9-compatible module declarations, while `patches/device-samsung-c5lte-lineage-17.1/0001-drop-obsolete-eng-module-tags.patch` normalizes all eight affected declarations to `optional` only for Android 10. The patch driver recognizes both version-specific final states idempotently.
- Android 10 no longer compiles the legacy `.conf` audio-policy path. `patches/device-samsung-c5lte-lineage-17.1/0002-use-xml-audio-policy.patch` enables XML policy and installs the existing MSM8952 Android 10 configuration plus its A2DP, USB, remote-submix and volume includes.
- Android 10's image builder requires a label for every root directory merged into system. `patches/device-samsung-c5lte-lineage-17.1/0003-label-firmware-modem-mountpoint.patch` labels the pre-existing `/firmware-modem` mount point as `firmware_file`; it does not add a new SELinux allow rule.
- The first installed ROM showed that init could not mount the already labeled `/efs` mount point under enforcing SELinux. `patches/device-samsung-c5lte-lineage-17.1/0004-allow-init-to-mount-efs.patch` grants only `mounton` on an `efs_file` directory to init; it does not grant EFS content access, change fstab, disable enforcing mode or alter any partition.
- LineageOS 17.1 recovery already contains the required minadbd-before-USB-config ordering, FunctionFS-ready transitions and USB-state restoration. The patch driver verifies those upstream semantics instead of applying the Android 9 recovery patch.
- `patches/device-samsung-c5lte-lineage-17.1/0005-force-legacy-recovery-functionfs.patch` disables Android 10 adbd's unsupported nonblocking FunctionFS AIO path on the Linux 3.10 kernel while retaining the legacy compatibility property.
- `patches/device-samsung-c5lte-lineage-17.1/0006-enable-recovery-adb-by-default.patch` enables unauthenticated root recovery ADB during early init. Hardware logs show `adbd` running automatically at 2.3 seconds; the remaining occasional host enumeration failure is a separate USB link issue rather than failure to start the daemon.
- `patches/device-samsung-c5lte-lineage-17.1/0007-drop-duplicate-cas-manifest-entry.patch` removes the device tree's legacy CAS 1.0 instance because Android 10 installs the same `IMediaCasService/default` instance from its CAS 1.1 service fragment. Keeping both makes libvintf reject the entire device manifest.
- `patches/device-samsung-c5lte-lineage-17.1/0008-use-android-10-power-hal.patch` replaces the removed QTI power 1.1 service module with Android 10's available 1.2 service, updates the device VINTF declaration and points the custom c5lte power library at the moved QTI header path. This is tied directly to 13 ANRs that all block `system_server` in `PowerManagerService.nativeInit()` waiting for the absent service.
- `patches/device-samsung-c5lte-lineage-17.1/0009-use-android-10-bluetooth-service.patch` selects Android 10's source-built Bluetooth 1.0 service executable without selecting its generic implementation. `patches/proprietary-vendor-samsung-c5lte-lineage-17.1/0001-drop-android-8-bluetooth-service.patch` removes the older QTI service executable and init rc while retaining `android.hardware.bluetooth@1.0-impl-qti.so`. This hybrid keeps the Android 10 process and platform dependencies but restores QTI's integrated Pronto SMD power-up, local-address, NVM-download and HCI-reset sequence. The earlier `vendor.bluetooth.status=on` property bypass and generic implementation were removed after hardware testing disproved them.
- `patches/device-samsung-c5lte-lineage-17.1/0010-allow-recovery-kernel-param-access.patch` grants the recovery kernel domain only the directory-search and link-read permissions required to reach `/dev/block/bootdevice/by-name/param`; QCOM's existing recovery policy already grants block-file read/write. This allows the shutdown-time `sec_param` worker to persist Samsung's normal restart value without extending the new traversal permissions to normal Android policy.
- `patches/device-samsung-c5lte-lineage-17.1/0011-force-legacy-system-functionfs.patch` selects Android 10 adbd's blocking FunctionFS path during normal-system early init, matching the hardware-proven recovery setting and avoiding Linux 3.10's unreliable nonblocking-AIO path.
- `patches/device-samsung-c5lte-lineage-17.1/0012-disable-codec2-for-legacy-gralloc.patch` sets `debug.stagefright.ccodec=0`. The Android 10 software Codec2 AVC decoder reproducibly dereferences a null pointer in `C2AllocatorGralloc::newGraphicAllocation()` against the legacy MSM8952 Gralloc stack; the platform-defined switch retains the working OMX path instead of replacing proprietary media libraries.
- `patches/device-samsung-c5lte-lineage-17.1/0013-allow-gnss-framework-peripheral-manager.patch` grants the GNSS HAL access to the framework servicemanager instance used by this legacy PeripheralManager. Hardware testing later proved that service discovery alone does not make GNSS register or vote, so this policy remains necessary plumbing rather than a complete repair.
- `patches/device-samsung-c5lte-lineage-17.1/0014-restore-stock-pm-proxy-voter.patch` restores CSA1's independently started 32-bit modem voter after the 64-bit Android 10 RIL path was proven to abort during PeripheralManager registration. The proxy is extracted only by the hash-pinned stock importer and is not committed.
- `patches/hardware-interfaces-lineage-17.1/0001-preserve-qti-bluetooth-service-groups.patch` retains the original QTI service's `system`, `wakelock` and `oem_2901` supplemental groups on Android 10's service definition. This preserves the reused implementation's wake-lock and device-specific QMI/diagnostic access while keeping Android 10's executable, capabilities and scheduling configuration.
- `patches/kernel-samsung-c5lte-lineage-17.1/0001-backport-memfd-create.patch` adds the native arm64 syscall at number 279, the compat ARM syscall at number 385 and the minimal shmem-backed implementation required by Android 10 ART. It follows the proven same-SoC MSM8952 LineageOS 17.1 backport revisions `9fdadeb84ca26cd9dd02c90e0a05c92ecab5e31d`, `3ab89c5a5b63897ff69e4ff3fb60aa26ffacae62`, `9f66eb8abe1679988010d9519f6d0acee4c780cd` and `2a66b8ee8ffe82ae944e768b0487a7cec7d4d1e5`. This deliberately implements ART's flags-zero use case without claiming full modern memfd sealing support.
- `patches/kernel-samsung-c5lte-lineage-17.1/0002-clear-stale-pmic-restart-reason.patch` clears any retained PMIC restart reason before normal restart dispatch and before power-off. Named recovery, bootloader and RTC restart targets immediately replace the cleared value through their existing paths. This narrowly tests stock `aboot`'s confirmed treatment of PMIC reason `1` as a recovery request without modifying bootloader, PARAM, FOTA or recovery-selection data.
- `patches/system-core-lineage-17.1/0001-disable-system-recovery-rewrite.patch` removes the system-root init service that can rewrite the separately managed recovery partition when a persisted setting is true. It does not remove recovery support, change the OTA's direct system/boot scope or affect recovery builds.
- `patches/system-core-lineage-17.1/0002-restore-libbase-logmessage-compat.patch` restores the legacy five-argument `android::base::LogMessage` constructor that Android 8 vendor prebuilts used and Android 10 removed. It forwards to Android 10's six-argument constructor with a null tag, matching the compatibility implementation retained by LineageOS 16.
- The 17.1 container creates a `forge` passwd/group entry for the host UID/GID. This is required because Android 10's Kati packaging stage resolves the numeric build UID through the container user database.

## Recovery USB transition fix

The repair-ROM installation log captures the failure sequence directly. minadbd opens FunctionFS, receives `FUNCTIONFS_BIND` and `FUNCTIONFS_ENABLE`, then terminates its first transport with `failed to submit first read, AIO on FFS not supported`. A physical disconnect generates `FUNCTIONFS_SUSPEND`; only then does minadbd report `failed to use nonblocking ffs, falling back to legacy`, initialize legacy FunctionFS successfully and expose a usable sideload transport. Both regular recovery adbd and the later minadbd process therefore select the kernel-compatible legacy path immediately. ## VINTF crash diagnosis and replacement

A controlled ordinary reboot of the EFS-fixed installation still stopped at Samsung's boot warning, but the complete persistent log proves that this is a later userspace failure. First-stage mount succeeded; userdata, cache, persist, modem, firmware, EFS and DSP all mounted; `ro.crypto.state=unencrypted` was set; zygote, SurfaceFlinger and the hardware composer started. At about 25 seconds, `hwservicemanager` PID 307 crashed with a null dereference in `android::vintf::HalManifest::getInstances()`, and its init restart action killed the main and HAL service classes. SurfaceFlinger then aborted after losing the hardware-composer service, explaining why no Android boot animation appeared.

The same log records `Cannot add manifest fragment /vendor/etc/vintf/manifest/android.hardware.cas@1.1-service.xml: HAL "android.hardware.cas" has a conflict.` The base device manifest declared CAS 1.0 `IMediaCasService/default`, while the Android 10 service fragment declared CAS 1.1 with the same instance. Libvintf rejects the complete device manifest on this conflict, `VintfObject::GetDeviceHalManifest()` returns null, and Android 10's `hwservicemanager` dereferences that unchecked null when a client calls `listManifestByInterface`. This also explains why its earlier transport queries could not find device-manifest HALs such as memtrack even though they were present in XML.
